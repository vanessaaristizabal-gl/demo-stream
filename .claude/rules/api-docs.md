# API documentation and contract

- The API is documented with **Scramble** (MIT): OpenAPI 3.1 generated from the code, served at `/docs/api` (UI) and `/docs/api.json`; local and testing are open, elsewhere admins only (`viewApiDocs` gate).
- Every controller class has `#[Group('...')]` and every public action has a docblock whose first line is the summary (a test fails on an undocumented route). Describe business rules in the docblock body (idempotency, who may call, what is blocked).
- Request shapes come from FormRequests, response shapes from API Resources (`{ data }` for one, `{ data, links, meta }` for lists); Scramble reads both, so keep them typed and never return raw models or arrays.
- `docs/openapi.json` is regenerated by a hook whenever you save API code (controllers, requests, resources, models, routes); commit it. `ApiDocsTest` fails if it is stale or a route has no summary. Run `cd backend && php artisan scramble:export` yourself only if the hook could not (for example a syntax error mid-edit).
- The frontend contract follows: update `frontend/src/shared/api/types.ts` and `frontend/e2e/mock-api.ts` in the same change.
- Errors use `GovernanceException` factories with a stable `error` code and HTTP status (409 locked/invalid transition, 422 validation/idempotency, 423 emergency stop, 403 role).

Docblock example and the rest of the conventions: `docs/standards/laravel.md` (section API documentation).
