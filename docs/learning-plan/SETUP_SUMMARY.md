# Setup summary: Claude Code for front-end and back-end work in Stream

| Piece                       | Where                                        | What it does                                                                                                                                                                                                      | How to use it                                                                                       |
| --------------------------- | -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Project context             | `CLAUDE.md`, `.claude/rules/`                | Conventions: tokens and base components, required states incl. partial failure, keyboard, one test per criterion, no `v-html`, no real accounts, UX and information design (tabs, accordions, wizard)              | Read automatically every session                                                                    |
| Product guide               | `docs/PRODUCT_OVERVIEW.md`                   | Who uses the app (strategist, approver, admin), what each page is expected to do, diagrams of the flow, the pages and the data, and the project structure                                                         | Read it first                                                                                       |
| Specs                       | `docs/specs/*.md`                            | Acceptance criteria and states per screen                                                                                                                                                                         | Write the spec first; it owns the truth                                                             |
| Skills                      | `.claude/skills/`                            | `screen-from-spec` (spec to component, one test per criterion, one story per state, then the reviewer), `create-vue-component`, `create-pinia-store`, `add-laravel-endpoint`, `design-language`                    | `/screen-from-spec docs/specs/<spec>.md`                                                            |
| Agents (read-only reviewers) | `.claude/agents/`                           | `screen-reviewer` (a screen vs its spec), `frontend-code-reviewer` (TypeScript, Vue 3, Pinia, tests, performance), `backend-code-reviewer` (PHP, Laravel, API design, Pest), `a11y-reviewer`, `write-path-guardian` | "Use the frontend-code-reviewer on `<change>`"                                                      |
| Hooks                       | `.claude/settings.json`, `.claude/hooks/`    | Block edits to env, secrets, keys and lockfiles, and destructive database commands; after each front-end edit: format, lint, type check, affected tests, screen check                                            | Automatic; exit 2 makes Claude fix it                                                               |
| MCP                         | `.mcp.json`                                  | Playwright MCP (walk screens, draft e2e) and Chrome DevTools MCP (accessibility tree, Lighthouse, traces); pinned, free, approved in `.claude/settings.json`                                                      | `/mcp` to see them connected; `npm run audit:devtools` runs the DevTools checks on every page       |
| Checks                      | `frontend/tools/`, `npm run ...`             | `traceability`, `budget`, `review:fixtures`, `audit:devtools`, `sync:codex`, `report`, axe in unit and e2e                                                                                                        | `npm run check`, `npm run e2e`, `npm run build && npm run budget`                                   |
| Plugin                      | `plugins/stream-frontend-kit`                | 6 skills, 3 reviewer agents, 2 hooks and 2 MCP servers; the conventions travel as skills generated from the rules                                                                                                 | `npm run plugin:build`; `claude plugin marketplace add ./plugins`; `claude plugin install stream-frontend-kit@stream-local` |
| Codex mirror                | `.codex/`, `.agents/`, `AGENTS.md`           | Generated from `.claude/` so the two never drift                                                                                                                                                                  | `npm run sync:codex` (a test fails when it is stale)                                                |
| Product pages               | `/accounts`, `/campaigns`, `/changelog`, `/admin` | Accounts with their own budget and an account page (Campaigns, Launch, Changelog); Campaigns with provider tabs, status filter and an Approvals tab; Admin with the emergency stop and OEM rulebooks. Launch, bulk change and ad copy run on a dev-only mock | `npm run dev`                                                                                       |
| Compliance report           | `docs/learning-plan/report.json`             | The learning plan exercise by exercise, per week, in English and Spanish (PDF)                                                                                                                                    | `npm run report`                                                                                    |
| Review log                  | `docs/learning-plan/REVIEW_LOG.md`           | What was rejected or corrected, and why                                                                                                                                                                           | Add a row every time                                                                                |
